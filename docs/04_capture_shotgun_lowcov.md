# 4. Capture versus shotgun, and low-coverage calling

This chapter covers two decisions that come after a library has passed a first authentication look: whether to shoot deeper or to capture, and how (not) to call or impute genotypes at low coverage. Commands are taken from opened READMEs or papers; they are not grape-tuned defaults we ran.

## Capture versus shotgun in the grape papers we opened

Ramos-Madrigal et al. (2019, abstract) and Cohen et al. (2023, full text) both used “target-enriched genome-wide sequencing” on archaeological grape seeds. The existing catalogue already notes in-solution capture around a grape SNP panel; the exact bait count used in each paper should be taken from that paper’s Methods, not guessed here. Cohen et al. 2023 (full text re-opened 2026-11-15 CST, PMC10151551, 121,375 bytes, sha256 92a5f83fb2bfe4e1c17175ca745f7ad2d0464c4172ebff2eff46f5de4f2f6805) state that libraries of samples A31–A37 “were enriched for a set of 10,207 SNPs according to Ramos-Madrigal et al. ( 22 ) and Laucou et al. ( 28 ).” That count is therefore taken from Cohen 2023. Whether Ramos-Madrigal 2019 or Laucou 2018 themselves print the number was not re-opened 2026-11-15 CST **[待确认]**. The count does not appear in Noraz et al. 2026 (full text re-opened 2026-11-15 CST, PMC13013926). The existing catalogue rows that present 10,207 as a Ramos-Madrigal or Laucou fact, or that also name Noraz as a source for the count, are not edited; an appended erratum row records the Cohen wording.

Noraz et al. (2026, full text) report “genome-wide ancient DNA data” from 49 pips; the capture-versus-shotgun details should be read from that paper’s Methods rather than assumed from the abstract alone (**[待确认]** if only the abstract is used for that distinction).

Carpenter et al. (2013, abstract; doi:10.1016/j.ajhg.2013.10.002), “Pulling out the 1%: Whole-Genome Capture for the Targeted Enrichment of Ancient DNA Sequencing Libraries,” is a whole-genome capture method paper (human-oriented in its dataset). It is a capture-methods citation, not a grape bait design.

A practical split used in the existing WORKFLOW, and consistent with these papers, is: shallow shotgun or a small screen first to measure endogenous content and damage; if those look usable, either sequence deeper or capture, then remap and deduplicate before genotyping. We did not open a single published threshold that says when a grape pip “must” go to capture (**[待确认]**).

Wales et al. (2012, abstract; doi:10.1371/journal.pone.0045644) describe “a cost-effective assay to prescreen ancient plant remains destined for shotgun sequencing.” That is a plant-remains screening paper, not a grape capture design.

Bolognesi et al. (2025, full text) is about maximising processable aDNA from archaeological grape pips before library construction and sequencing; it does not replace a capture-versus-shotgun decision after screening.

## Alignment reminders (already in the WORKFLOW)

Schubert et al. (2012, full text opened 2026-11-15 CST, PMC3468387, 152,427 bytes, sha256 2fc0c97a91215a7488720f247b5fbf86ba42812417770f2ca603617764f77585; doi:10.1186/1471-2164-13-178) is the source used in the existing WORKFLOW for `bwa aln -l 1024` on Illumina data. The paper states, verbatim: “For both Illumina and Helicos sequencing data, the seed was disabled in the optimized set of mapping parameters (−l 1024).” The same paper says of BWA: “These thresholds may be manipulated using the -n option, with a default value of 0.04.” Parameter combinations such as `-n 0.01 -o 2` remain attributed in the WORKFLOW to widespread human-aDNA practice, with the original Green et al. 2010 source **[待确认]**; they are not Schubert’s stated default. This chapter does not mix those values into a new “grape default.”

The capture-generator script in this repository (`scripts/adna_capture_pipeline_generator.sh`; listed in REMOVALS.md) uses `-l 1024 -n 0.01` and AdapterRemoval `--minlength 25`. `scripts/dsdna_preprocess.sh` (also listed in REMOVALS.md) uses `-l 1000` and, at line 12, `--minlength 30`. The WORKFLOW default for AdapterRemoval is `--minlength 30`. AdapterRemoval’s own length default, opened 2026-11-15 CST, is 15: the v2.3.4 man page (`AdapterRemoval.1`) documents `--minlength` with “Defaults to 15.”; the 3.0.2 manpage (https://adapterremoval.readthedocs.io/en/v3.0.2/manpage.html) documents `--min-length` with the same “Defaults to 15.” sentence. These values are not endorsed here as a new standard.

## Low-coverage calling

ANGSD (Korneliussen, Albrechtsen and Nielsen 2014, doi:10.1186/s12859-014-0356-4; README https://github.com/ANGSD/angsd, opened, 1,271 bytes) is the preferred likelihood route already catalogued. The advice not to force diploid hard calls at very low coverage, and the statement that pseudo-haploid random draws (sequenceTools `pileupCaller`; README opened) discard within-individual heterozygosity and must not be used as a direct heterozygosity estimate, are this repository’s teaching judgements: those sentences are not in the opened ANGSD or sequenceTools abstracts or READMEs. For single-stranded libraries, the existing WORKFLOW already points to `pileupCaller --singleStrandMode`. The opened sequenceTools README treats `--singleStrandMode` as an experimental option and describes it for use with merged reads; confirm against that README before a run.

## Imputation is not a grape-ready step

Rubinacci et al. (2023, full text, PMC10335927; doi:10.1038/s41588-023-01438-3) describe GLIMPSE2 as imputation of “low-coverage sequencing data from 150,119 UK Biobank genomes.” That dataset is human. The GLIMPSE README (https://github.com/odelaneau/GLIMPSE, 4,057 bytes) documents low-coverage imputation from a haplotype reference panel. The existing WORKFLOW already restricts grape imputation to after a pre-registered accuracy test on modern grapes downsampled to ancient depths (AM17, project 20). That pre-registration still needs to lock a depth grid, MAF-binned *r*², and a pass line before the test is run; the reference panel must exclude clones and first-degree relatives of the test individuals (this repository’s design requirement, still **[待确认]** as a written protocol). This chapter does not invent a grape GLIMPSE2 parameter set, and it does not treat the UK Biobank accuracy figures as grape figures.

## Relatedness tools need a grape calibration

READv2 (doi:10.1186/s13059-024-03350-3; README opened) and KIN (doi:10.1186/s13059-023-02847-7; README opened) estimate relatedness from low-coverage data. Noraz et al. 2026 (full text re-opened 2026-11-15 CST, PMC13013926) state, in Methods, after describing the READv2 P0 procedure: “This procedure was, however, originally developed for human data and may, thus, not immediately apply to species with high heterozygosity and mixed sexual and clonal reproduction systems, such as grapevine.” That sentence is about READv2 as used in that paper; it is not a KIN README sentence.

The KIN repository README (re-fetched 2026-11-15 CST from https://raw.githubusercontent.com/DivyaratanPopli/Kinship_Inference/master/README.md, 8,590 bytes, sha256 d8fb5c88f50e0ae5cd7528621e6db2b530b0f44233ab6ea58d6e887eb4ee488c) documents `-N` under the heading “Running KINgaroo”, not under “Running KIN”. The README says, verbatim: “N: Total number of chromosome pairs. Default=22”. It does not say that 22 is the human autosome count. The same KINgaroo section says input BAMs have “chromosomes (represented by 1,2,..,X,Y)”; grape assemblies typically use names such as chr01. That naming mismatch is a repository caution, not a sentence in the KIN README.

Canaguier et al. 2017 (full text opened 2026-11-15 CST, PMC5612791, 86,734 bytes, sha256 69beb1622f4a32a070df0b4798752d6856c9d28fa46c00e74d2d9573c7bccca4; doi:10.1016/j.gdata.2017.09.002; print year 2017), “A new version of the grapevine reference genome assembly (12X.v2) and of its annotation (VCost.v3),” state: “The v2 chromosome assembly therefore consists of 19 chromosome sequences (chr01 to chr19) and one chromosome random pseudo-molecule (chr00).” Setting KINgaroo `-N 19` to match those 19 assembled chromosomes is a repository judgement based on that sentence; the KIN README does not mention grape or 19 as a tool default for Vitis **[待确认]**. The Jaillon et al. 2007 abstract (doi:10.1038/nature06148; EuropePMC core opened 2026-11-15 CST) does not state the chromosome number, and was not used as the source for 19.

Noraz et al. 2026 already report a grape READv2 calibration: P0 = 0.238, for *V. vinifera* subsp. *vinifera* / ACG material only; a separate threshold is used for *sylvestris*; false-positive rate 0.4%; clone identification 99.3% / 94.6%. The “identical” class in that calibration was constructed from pseudohaploidised duplicates. Whether that calibration was itself downsampled to ancient depths remains **[待确认]** (supplementary figure 17 / data 26 were not opened). READv2’s default median normalisation assumes that most sample pairs are unrelated; a collection rich in clones can violate that assumption, so a fixed P0 and group-wise analysis are safer (this repository’s judgement, informed by that paper).

If KIN or a new READv2 calibration is run on grape, the minimum design is: modern clone and relative pairs, downsampled to matching depth, with a pre-registered pass rule, and with seed-tissue origin recorded, because seed coat versus embryo can affect a “genetically identical” call (tissue-origin caution already in WORKFLOW, still **[待确认]** for *Vitis*). KING hard-call cutoffs from modern SNPs are not a drop-in substitute at ancient depth.
